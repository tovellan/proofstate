# ProofState 0.4.0

ProofState 0.4.0 defines portable YAML scalar behavior and closes remaining
JSON-compatibility gaps in structured evidence.

## Changed

- YAML inputs use YAML 1.2 Core scalar resolution on PyYAML 6.x, restricted to
  values representable in JSON. This is not a claim of full YAML 1.2 grammar
  support; YAML directives are rejected before parser conversion.
- Artifact check expectations accept only JSON-compatible values. Numeric
  operators require finite numbers and reject booleans and numeric-looking
  strings.
- JSON Pointer array tokens must be canonical ASCII decimal indexes: `0` or a
  nonzero digit followed by ASCII digits. Object keys continue to use their
  exact decoded token.
- The installed conformance corpus now has 17 cases, including seven YAML cases
  for Core scalars, legacy numeric spellings, merge keys, non-finite values,
  and non-string mapping keys.
- Structured documents reject more than 125,000 scalar and collection nodes.
  YAML enforces the limit before constructing its object graph, bounding
  expansion of byte-limited inputs.
- JSON and YAML apply a deterministic 4,300-digit decimal integer limit without
  depending on Python's mutable process-wide conversion setting.
- Repository and distribution gates reject symlinks and special files in
  tracked or package-source boundaries before reading their content.
- Test-symbol evidence caps Python source at 64 KiB before AST parsing, and
  repeated identical machine evidence is verified once per evaluation. Parsed
  symbol indexes are retained for sources admitted by the cumulative work
  budget.
- Structured object `contains` checks use one direct key lookup.
- Evaluations reuse immutable file digests and retain parsed artifacts and
  attestations under aggregate input-byte and structured-node budgets. List
  membership builds one type-exact structural index per retained list and
  memoizes each retained composite subtree digest once.
- Evaluations admit at most 256 uncached regular evidence sources and 10 MiB of
  source input. Tree metadata is fetched in at most 256 bounded,
  prefix-separated batches; later sources, lookups, or structured parses fail
  closed with `PSE104` when cumulative work is exhausted.
- Git worktree discovery preserves the exact absolute path, including trailing
  whitespace characters, and rejects malformed or relative command output.
- Evaluation cache keys remain type-exact for all accepted JSON strings, and
  returned dictionaries do not alias retained result state.
- Conformance cases normalize unreadable fixture files to
  `fixture_unavailable` instead of leaking an operating-system exception.
- Release tags require the generic tagger and exact annotation. The release
  workflow publishes a complete draft under owner-enforced immutability, then
  verifies the exact release record and GitHub's automatic release attestation.

## Migration

| Earlier plain scalar or pointer | 0.4.0 behavior | Migration |
| --- | --- | --- |
| `yes`, `no`, `on`, `off` | String | Use `true` or `false` for a boolean. |
| `012` | Decimal integer `12` | Use `0o12` for octal or quote text. |
| `0b10`, `1:20`, `1_000` | String | Rewrite as a decimal number when numeric meaning is intended. |
| `1e3` | Floating-point number | Quote it when text is intended. |
| Timestamp-looking scalar | String | No migration is required. |
| Plain `<<` mapping key | Rejected | Quote `"<<"` when it is an ordinary string key. |
| `%YAML` or another directive | Rejected | Remove the directive and use the documented restricted profile. |
| Array pointer token `/01` | Not an array index | Use `/1`; `/01` remains valid when traversing an object. |
| Structured document over 125,000 nodes | Rejected | Reduce or split the document; mapping keys and values each count as nodes. |
| Test-symbol source over 64 KiB | Rejected before AST parsing | Split the module or use file and result-artifact evidence. |
| Decimal integer over 4,300 digits | Rejected in JSON and YAML | Shorten it or encode an opaque identifier as a quoted string. |
| Evaluation over 256 uncached regular sources or 10 MiB total | Later sources fail with `PSE104` | Split the scorecard or reduce evidence inputs. |
| Encoded evidence path at or above 16 KiB | Rejected with `PSE104` before Git tree lookup | Shorten the repository path. |
| Encoded scorecard path at or above 16 KiB | Rejected with `PS001` before Git tree lookup | Shorten the repository path. |
| Artifact or attestation parsing over 1,000,000 cumulative charged nodes | That parser latches closed with `PSE104`; a failed parse is charged 125,000 nodes | Reduce, fix, or split structured evidence. |

Scorecard, attestation, result, error, and conformance schema identifiers remain
`v1alpha1`. The documented compatibility policy permits this behavior change in
a minor release before 1.0.
